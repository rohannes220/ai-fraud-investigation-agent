
# AI Fraud Investigation Agent

An explainable, AI-assisted financial crime investigation system built with **Python, FastAPI, PostgreSQL, SQL, and LLMs**.

The application separates **fraud detection from AI-assisted investigation**: deterministic rules identify suspicious transaction patterns, while an LLM reviews the supporting evidence and drafts a structured investigator case note.

**Pipeline:**
`Transactions → Fraud Rules → Risk Scoring → Alerts → Evidence Retrieval → LLM Review → Investigator Case Note`

---

## Overview

Financial institutions need fraud-monitoring systems that are transparent, explainable, and auditable.

This project demonstrates a simplified financial crime investigation workflow where suspicious transaction activity is identified using deterministic Python rules. Once an alert is generated, the relevant transaction evidence is passed to an LLM to assist an investigator by producing an evidence-grounded case summary.

The LLM does **not** determine whether fraud occurred. Its role is limited to reviewing supplied evidence and assisting with the investigation process.

All customer and transaction data used in this project is synthetic.

---

## Key Features

* Generates reproducible synthetic banking transaction data
* Stores customers, transactions, alerts, and investigations in PostgreSQL
* Detects suspicious transaction patterns using explainable Python rules
* Assigns transparent risk scores based on triggered indicators
* Retrieves supporting transaction evidence for generated alerts
* Uses an LLM to draft structured investigation case notes
* Constrains AI responses to supplied evidence
* Prevents the LLM from making definitive fraud determinations
* Provides REST APIs through FastAPI
* Includes a browser-based investigation dashboard
* Supports deterministic fallback reports when an LLM API is unavailable

## Fraud Detection Rules

The detection engine evaluates transaction histories for several suspicious patterns.

### Unusual Transaction Size

Identifies transactions that are unusually large relative to expected activity.

### Rapid Large Transfers

Detects multiple high-value transactions occurring within a short period.

### Repeated Near-Threshold Transfers

Flags repeated transactions occurring near predefined monitoring thresholds.

### Multiple New Counterparties

Identifies activity involving an unusual number of previously unseen counterparties.

Each triggered rule contributes to an alert and transparent risk score that can be reviewed by an investigator.

## AI Investigation Workflow

The AI component is intentionally separated from the fraud-detection logic.

```text
Synthetic Transactions
        ↓
PostgreSQL
        ↓
Python Fraud Rules
        ↓
Risk Score + Alert
        ↓
Supporting Transaction Evidence
        ↓
LLM Investigator
        ↓
Evidence-Grounded Case Note
        ↓
Human Investigator
```

The LLM receives the evidence associated with an alert and generates an investigation summary.

It is explicitly instructed to distinguish suspicious indicators from proof of fraud and not to make the final fraud determination.

This creates a **human-in-the-loop (HITL)** workflow where AI assists the investigator rather than replacing the investigator.

---

## AI Guardrails

The project includes several controls around the LLM's role.

### Evidence-Constrained Generation

The model is provided with the transaction evidence associated with the alert rather than being asked to independently determine what happened.

### Restricted Decision Authority

The LLM is explicitly instructed not to conclude that fraud occurred.

### Separation of Detection and Generation

Fraud indicators and risk scores are generated by deterministic Python logic rather than by the LLM.

### Human-in-the-Loop

AI-generated case notes support an investigator, while the final determination remains with the human investigator.

Together, these controls reduce unsupported AI conclusions and create a more transparent and auditable investigation workflow.

## Running the Project

### 1. Configure the Environment

```bash
cp .env.example .env
```

Add an `OPENAI_API_KEY` to `.env` to enable LLM-generated investigation reports.

If no API key is provided, the application uses a deterministic fallback report.

### 2. Create a Python Environment

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3. Start PostgreSQL

```bash
docker compose up -d db
```

### 4. Initialize the Database

```bash
PYTHONPATH=. python scripts/init_db.py
```

### 5. Generate Synthetic Transactions

```bash
PYTHONPATH=. python scripts/seed_data.py
```

### 6. Run Fraud Detection

```bash
PYTHONPATH=. python scripts/run_rules.py
```

### 7. Start the Application

```bash
PYTHONPATH=. uvicorn app.main:app --reload
```

Open:

`http://127.0.0.1:8000`
